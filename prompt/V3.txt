# 提示词 v3（第三轮，定向修补薄弱环节）

> 记录时间：2026-11-05 20:12
> 目的：针对 v2 的"关系/多重性/图谱实体缺失"三处硬伤追加定向约束

```text
【建模意图】
同上一次（物联知图平台 · 通过图谱下发设备动作），本次只修正以下三处，
不要改动已经正确的部分，仍只输出两段 PlantUML 代码。

【追加约束 A：参与者白名单】
参与者和外部系统只允许出现：系统管理员、运维工程师、普通用户、
网关设备。MQTT 代理、数据库、消息队列属于系统内部实现，
不能出现在用例图中（如果你认为需要，请用 note 说明而不是画成 actor）。

【追加约束 B：类图必须覆盖"知识图谱"这一侧】
必须包含：KnowledgeGraph（含 nodes/edges）、GraphNode（含 nodeId/etype/props/version）、
GraphEdge（含 rtype/src/dst）、Ontology（含实体类型与关系类型定义）。
这些类与 Device 的关系是"映射"（一台 Device 在图谱中对应一个 GraphNode），
请用依赖或注释表达，不要用组合。

【追加约束 C：关系与多重性逐条声明】
- Gateway 与 Device：1 对 0..*，关联名为"连接"，方向由 Device 指向 Gateway（设备"经由"网关）；
- Location 与 Device：1 对 0..*，关联名为"位于"，方向由 Device 指向 Location；
- Location 与 Location：0..1 对 0..*，自关联，表示层级；
- Device 与 Sensor / Actuator：泛化，Device 为抽象父类；
- Device 与 Command：1 对 0..*，命令由设备执行；
- Command 与 PermissionChecker：依赖（校验时使用，不持有）。

【期望输出】
两段 PlantUML：一段用例图、一段类图，无需文字说明。
```

## v3 采用情况

v3 是本实验最终采用的提示词版本。AI 输出见 `ai_output/ai_uc_图谱操控_v3.puml`
与 `ai_output/ai_class_图谱操控_v3.puml`，评估结论见实验报告第 7 章。

| 指标 | v1 | v2 | v3 |
| --- | --- | --- | --- |
| 参与者数量（正确数/总数） | 5/7 | 4/5 | 4/4 |
| 用例数 | 11 | 9 | 8 |
| 类数 | 6 | 9 | 12 |

可见"结构化要素"带来第一次跃升，"定向约束"带来第二次跃升；
但类数达到 12 仍少于手工模型的 23，说明模型对"实体识别的完备性"始终偏保守。
