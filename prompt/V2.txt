# 提示词 v2（第二轮，补全结构化要素）

> 记录时间：2026-11-05 15:40
> 目的：按"建模意图 / 系统边界 / 参与者清单 / 约束条件 / 输出格式"五要素重写

```text
【建模意图】
为"物联知图"平台建立"通过图谱下发设备动作"这一核心用例的需求模型，
用于课程验收，模型需可直接渲染，不接受伪代码。

【系统边界】
系统名：物联知图平台。边界内：图谱可视化、设备接入、指令下发、告警、权限。
边界外（只能作为参与者或外部系统）：MQTT 消息代理、网关设备、图数据库、短信网关。

【参与者清单】
1. 运维工程师（主要操作者，可查看图谱、可下发动作）
2. 系统管理员（维护设备档案与角色权限，可下发高风险动作）
3. 普通用户（值班员，只读）
4. 网关设备（外部系统，上报遥测、回传执行回执）

【约束条件】
- 一条指令在下发前必须经过：角色权限、设备归属、动作白名单、参数区间 四项校验；
- 指令有"待确认—下发中—等待回执—成功/失败/超时"的状态，允许超时重试 2 次；
- 高危动作（如开阀、开门）仅系统管理员可执行；
- 图谱中每台设备必须是某个位置节点的下级，且连接到一个网关。

【期望输出】
1. 一个 PlantUML 用例图（@startuml ... @enduml），使用 package 划分功能域，
   标注 include / extend 关系；
2. 一个 PlantUML 类图，包含 Device 抽象、Sensor / Actuator 子类、
   Command、CommandExecutor、PermissionChecker，标注多重性与关联方向；
3. 类名与属性用英文，注释用中文；不要输出解释性文字，只输出代码块。
```

## v2 输出问题（自评）

比 v1 明显改善：参与者收敛到 4 个、出现了 include 关系、给了 Command 类。
但仍有三处硬伤：

1. **把 MQTT 代理写成了第二个参与者**，违反"边界外基础设施不是参与者"的约束；
2. **类间关系错了**：`Gateway "1" -- "1" Device`（真实是一网关多设备），
   且 `Sensor <|-- Device`（泛化方向反了，父类应在左）；
3. **遗漏了知识图谱侧的核心类**，整张类图是"纯物联网"，看不到"知图"。

结论：要素齐了，但"关系与多重性"这一薄弱环节仍需要更明确的指向性约束。
进入 v3。
